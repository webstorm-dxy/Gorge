# C# Parity 分步解决方案（执行路线图）

> 基于 `reports/csharp-parity-todo.md` 的不一致清单，制定分阶段解决方案。
> 执行约定（已与用户确认）：
> - **按依赖顺序推进**（D→E→F→G→…）
> - **每步验收 = 单测 + 端到端（.g→gorgec→gorge_runner）+ 零 warning**
> - **每个 Phase 开始前，向用户确认该 Phase 的详细子方案与关键决策点**
>
> 沿用 Phase A–C 工作模式：小步增量、每步可独立验证、补中文注释与单测。

---

## 依赖关系图

```
D1(break/continue) ── 独立，最先做
E1(类型推导) ─┬→ E3(cast)  ─┐
E2(转换规则) ─┴→ E4(重载)  ─┴→ F1(接口方法映射)
                             └→ G3(注入器构造)
E1 → G1(注入器字段访问)
G2(注入器字面量) → G3, G4(@Inject/元数据)
F2(native 被继承) ── 依赖既有 A5，独立
```

## 里程碑意义

- **完成 D+E**：基础语言正确（循环控制、类型转换、重载）——任意普通 Gorge 程序可正确编译执行
- **完成 F**：面向对象特性完整（接口、native 继承）
- **完成 G**：注入器主线打通——**可真正构造 Gorge 谱面数据**（框架核心价值）
- **完成 H**：谱面数组数据可用
- **完成 I–K**：高级特性、优化质量、全量框架
